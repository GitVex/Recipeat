# Extraction

There are three routes and one recipe shape (`shared/types/recipe.ts`). None of them stores anything. `POST /api/recipes` saves whatever the user keeps, after `validateRecipe`. Text and photos go to Gemini (`server/extraction/gemini.ts`) in a single call each, constrained by `recipe-draft.schema.json`. A website runs no model: the fetcher reads it with `recipe-scrapers` (falling back to schema.org markup) and splits ingredient lines with `ingredient-parser`. An Instagram post is a website import. The fetcher reads it logged out with instaloader, tries up to three links from the caption, then sends the caption and images to the model together. Private posts are out of scope.

The pipeline in `server/extraction/` reads the input, asks the model or fetcher, then runs `parseExtraction`, which clamps and recovers instead of failing, then `normalizeRecipe`, which parses quantities, finds measurements in steps and links them to ingredients. `originalText` is kept on every line. The fetcher may emit only units `parseQuantity` also knows, and `units.json` is shared to keep the two in step. `npm run test:extraction` runs the pipeline with a fake `fetch`, no model needed.
