# Database

Postgres runs as its own Compose project (`docker/compose.db.yaml`, container alias `recipeat-postgres`) on `recipeat-db-net`. It stays off the fetcher's network, and the app is the only client. The app queries through Kysely (`server/database/schema.ts`, `useKysely()`), and `jsonb` is written with its `json()` helper, never `JSON.stringify`. Migrations are plain `NNN_name.sql` files in `server/database/migrations/` (001 recipes, 002 collections, 003 tags, 004 preferences, 005 images). They run at startup under an advisory lock, one transaction per file, recorded in `schema_migrations`. A failed migration stops the app from serving, and an applied file is never edited. Without `NUXT_DATABASE_URL`, storage routes answer 503.

The tables: recipes are owned by `owner_sub`, with lineage columns and one pinned version per line. Collections hold versions in order. Tags hang on a line's root and are unique per owner regardless of case. Preferences are one `jsonb` document per person, checked against `PREFERENCES` in `shared/utils/preferences.ts`. Images are `BYTEA` rows in two browser-made sizes, read only through `/api/images/{id}`. Every foreign key carries `owner_sub`. Backups are manual: `docker exec recipeat-postgres pg_dump -U recipeat recipeat`.
