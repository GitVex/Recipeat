# API map

The app's routes live in `server/api/`. Everything under `/api` except `GET /api/extract/sites` needs the encrypted `nuxt-oidc-auth` session cookie. It is minted only by the browser OIDC flow, so for manual testing, sign in and copy the cookie from DevTools. `GET /api/me` checks that it works. Another user's resource answers 404, never 403. Error messages are sanitized: the detail is in `docker logs recipeat-app`. The routes cover extraction (`/api/extract/{text,website,photo}`, which store nothing), recipes and their lineage (`/api/recipes`, `/{id}`, `/progressions`, `/variants`, `/pin`, `/history`, `DELETE` with `?dryRun=true`), filters on the listing (`q`, `tag`, `ingredient`, `maxTime`, `minPortions`, `maxPortions`, `source`), collections, tags, photos and images (`/api/images/{id}`, immutable-cached), preferences, and similar recipes through SearXNG.

The fetcher (`services/recipeat-fetcher`) has no auth and publishes only on `127.0.0.1:8103`. Reach it through `ssh -N -L 8103:127.0.0.1:8103 root@VPS`. FastAPI serves its contract at `/docs`. Its routes are `GET /health`, `GET /sites`, `POST /fetch` (public addresses on ports 80/443 only), `POST /instagram` (by shortcode) and `POST /ingredients`. The app reaches it over `recipeat-fetch-net`, never over the loopback port.
